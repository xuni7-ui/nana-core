# nana-space-live/v2

Canonical Python DTO/JSON Schema/OpenAPI/TS declarations are generated from
`life/live_api/contracts.py`. V1 remains separate development-only/offline.
Envelope: realm, subject_id, lineage_binding, owner_epoch, run_generation,
session_generation, revision, as_of_us, coverage, privacy_scope, source_refs,
capabilities, execution_authority=false, data. No second Subject authority.

All pages read actual developer Core in HTTP/browser qualification. Empty data is
NO_DATA, unavailable is explicit. These are not live-cloud deployment claims.
Personal scope and actual private migration remain separate gates, not fabricated
with public fixtures. APK and Web share the same source, DTOs and Core.

Web: POST session→Secure HttpOnly SameSiteStrict cookie + memory-only CSRF;
Origin/Host validation, no CORS. Bootstrap safely renews same-session CSRF after
reload. Native: one-time name/role-bound pairing→native encrypted refresh binding;
refresh/access never cross JS, localStorage, URL, push, export or APK source.
Native credential exchanges reject browser Origin. Native op map is finite,
HTTPS-only, no redirect/custom trust bypass. Android backup/transfer excluded.

POST messages/commands/host operations carry client_request_id,idempotency_key,
expected_revision,run_generation,owner_epoch. Pending receipts recover UNKNOWN;
no blind retry/fallback, old generation never replays. Host confirmation is
single-use,90sec,role/op/revision/release-bound. Current bounded receipt store
holds256 entries then explicitly requires operator archival; does not silently
evict keys. This capacity is a staging limit to resolve before extended daily use.
GET events returns metadata invalidation cursor; generation/gaps require a fresh
snapshot, never command replay. All response bodies/no-store and no content logs.
Withdrawal changes privacy watermark; cached reply wording is discarded.

External content cannot populate extra authority fields (strict DTOs), create
Grants, alter identity, rewrite Manager or turn relationship into execution rights.
Scoped memory withdrawal was fixed at this new gateway boundary. Compatibility
preserves current autonomous motives/research/learning/tools/self-extension; no
global capability disabled. Future open web/social/skill execution needs targeted
attack qualification. Sanitizing metadata is not an intelligence or agency filter.

Foreground notification permission/native channel/deep-link code exists. True
background delivery has no provider configured and is NOT_QUALIFIED, not a push
success. Physical notification permission/delivery must be reviewed on the user's
phone later. The internal debug signing key is not a production identity/key.

Device pairing defaults to Reader+Conversation. An already authenticated Host Admin
can explicitly select Manager+HostAdmin for its own phone; backend enforces role
subset, one-time expiry/name and revocation. Relationship significance does not
supply any of these roles. The same APK can manage Core only after that explicit
controller grant; no high-privilege shared server secret is embedded in it.
