# 切换模型保留路由策略，失败后遵守目录冷却

原高级界面与手机简易设置沿用授权配置命令及 CAS。切换模型时沿用当前路由的隐私范围、启停状态、超时、费用、上下文与输出限制。保留备用顺序，升为主模型的选项从备用删除。只有新建路由使用原默认配置，缺少隐私字段的旧投影沿用 Core 的 PUBLIC 默认。原版实际反例将 185000 ms / 0 限额与停用状态改成固定值。新用例确认浏览器提交保持原值与预期版本。

复用原 BFF 已返回的可选 `retry_after_ms`，简易与高级两界面从鉴权失败等目录响应共享同一倒计时，期满仅恢复按钮。旧版受控失败反例仍可立即再次点击。新 390 视口用例观察到两个入口在 3 秒内同时锁定，期满不自动发请求。Android 原生错误桥源码传递同一字段，SDK 合成契约只接收 0–10000 的整数，越界、字符串和旧缺省仍按原错误处理。原会话失效和运行权限继续由既有入口校验。

104 单元、TS/Vite 和 4 项 390 视口受控场景通过，真实 Provider 0。环境无 Android JDK/SDK，Java 源码尚未经 APK 构建或真机验收。当前使用 302 固定候选和原正式选择，合入此源码的匹配 Web/Android 留到后续交付节点。
