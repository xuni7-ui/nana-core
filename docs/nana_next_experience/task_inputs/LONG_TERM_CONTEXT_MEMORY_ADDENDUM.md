# Long-term context, memory quality and latency — user addendum (2026-11-06)

This supplements the existing ten-domain refinement mission, not a second memory or migration project. Preserve One Subject/Store/Loop, original C, Manager/Grant/privacy and the existing migration owner. Core long-lived quality is the objective; cache hit rate and token reduction alone are not success.

1. Budget the actual model/request path, including serialized messages, role inputs, tool schemas and output reserve. Prioritize identity, currently valid facts, significant relationships, commitments and necessary evidence. Never inject the entire history. Separate provider-reported tokens from measured or estimated tokens and disclose tokenizer/model limitations.
2. Reuse ContextAssembler, MemoryService, MaintenanceService, semantic/lexical retrieval and routing. Improve consolidation, evidence-based importance, hot/cold selection, corrections, temporal validity and hybrid retrieval where an actual gap is demonstrated. No automatic seven-day erasure or independent memory authority.
3. Verify the authoritative live Core Store/index mapping with the existing migration owner: active Subject, schema and source versions, memory/source IDs, embedding model/dimension, index generation, deletions and freshness. This is NOT VERIFIED by the code inventory or an offline clone. No private records or live production mutation are authorized by this addendum. Missing safe host evidence blocks only live qualification.
4. Establish frozen synthetic corpora at 1k/10k/100k and a larger feasible size with independent held-out queries, same model, permissions, hardware, policies, corpus/query digests and warm/cold conditions. Measure false recall (wrong entity/time/retracted/unsupported), recall of eligible relevant evidence, source correctness and abstention. Report denominators, P50/P95 retrieval and assembly latency, wire input/output tokens, provider calls, conservative reservations and confirmed/unknown actual cost separately. Synthetic runs with zero provider calls must not report real model naturalness or billing.
5. Baseline first, then one substantive change, then same-condition comparison. Investigate repeated retrieval/assembly, unnecessary serial cognition and background competition without removing C independent judgment, emotional relevance, autonomous activity, deep learning or verification. Compare quality as well as resources. Freeze the old method and rollback point before adoption.
6. Feed real retrieval errors and timing feedback into the existing sourced Experience/S8 path. Candidate policies require independent unseen evaluation, counterexamples, source-withdrawal handling and bounded adoption/rollback. No model self-rating or developer optimization counts as Nana learning; no direct overwrite of production strategies.
