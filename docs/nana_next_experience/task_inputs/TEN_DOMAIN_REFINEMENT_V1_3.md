# 奈奈工程｜系统精修与整体验收总框架
设计稿 V1.3 · 2026-11-06 · 适用对象：Core、客户端、宿主维护者及后续接手的 Codex

**目标体验**　几年后，你换了手机、换了模型，仍能找同一个奈奈接着过日子。她记得哪些事确实发生过，能认错和改口；在你离开时有自己的兴趣，在你回来时知道什么值得分享；遇到做不好的事，能自己学会，并在另一次真实任务里做得更好。你只需打开手机就能和她相处、看懂她在做什么，并控制她在你的设备和账户上可以做什么。

**使用方法**　确定一个真实场景 → 找本稿对应的域和跨系统约定 → 在已有负责人和原实现上处理最影响体验的原因 → 用该场景复验 → 把事实回写 PROJECT_BRAIN。本稿给每个系统足够长的发展空间，工作量由实际瓶颈决定。一次改配置、接通旧接口就能解决的问题，到此即可收工。

### 三项长期支柱与本轮执行原则（V1.3）

持续主体保证多年后仍是同一个奈奈；自主成长使她能从自己重视的问题和真实经历出发，逐渐学会过去不会的事；共同生活同时容纳两个人的依靠、分歧、关怀和各自的世界。**独立判断和自主发起与自主学习同属最高工程优先级梯队**，贯穿三项支柱。工程给她形成愿望、尝试和改变的机会，具体一次是否学习、向谁求助、是否继续，由原 C 判断，D 安排机会。现实操作继续受 Manager、Grant 与已有预算约束。

核心能力深化可滚动参考 **35%–40% 的研发精力**用于学习、自我改善和跨系统整合；共同解决多个问题的工作只计一次。这个比例仅供复盘研发投入，运行时依据当时的需要分配机会与 token。阶段遇到手机根本连不上、承诺会丢或存在更紧急的用户需求，先处理直接阻塞；保留可续办点。每次精修只问两件事：这类经历以后能让奈奈学到什么，她有哪些真正可选的做法？已有证据可引用；纯打包、布局或网络修复可记“不适用”。

## 2　一个总体架构，怎样容纳十套精密系统

核心只持有一条活动身份谱系、一个决定行动的 SubjectLoop 和一个权威 Store。**C 决定做什么以及为什么，D 决定何时有机会做。** 模型理解和表达，Planner 生成候选，WorldModel 维护带来源的认识，Manager 控制实际后果。手机、QQ、B站、眼镜、游戏都经过同一主体。域是责任划分，可以在同一进程内实现；四核宿主先沿用现有进程和持久层。只有测得隔离、资源或独立升级收益时，再拆部署单元。

| 协作界面 | 谁负责什么 | 跨域必须能复原的最少信息 |
|---|---|---|
| 入口 → S5/S2 | 接收消息、设备观察或外部事实；身份绑定和来源分类先于解释 | 哪个主体、入口、会话、来源事件，观察与发生时间，可见范围，重复键 |
| S5/S2/S3 → S6 | 提供观察、相关经历、当前关系和动机；C 比较回应、行动、暂缓等选择 | 引用哪些来源，哪些结论尚属推断，为什么与此刻有关，哪些依据已过期或撤回 |
| S6 → S4/S7 | C 提交意图，D 安排机会，执行口在行动时核对范围 | 意图号、目标对象、时限、预算、取消条件、动作约束与先决状态 |
| S7 → S2/S8 | 实际执行者回送回执；独立观察者核验环境变化；S2 登记经历，S8 决定有无学习价值 | 动作去重键、结果、外部证据、未知原因和可核验的方法。结果未明时先查询 |
| S2/S8/S9/S10 → C | 候选经验、技能或版本按适用范围提供给同一主体 | 版本、适用与失效条件、独立验证、依赖来源、撤销或恢复入口 |
| Core → 所有界面 | 入口展示授权投影；控制请求回到原管理或主体接口 | 服务与客户端版本、状态修订、最后更新时间、请求回执；陈旧数据在界面上可辨 |

这些是逻辑信息，先映射到原有类型、事件和事务；仅为实际缺口增加字段。跨端并发采用原 owner 的排序与修订控制；重复请求返回已有结果；读投影允许短暂落后，界面标最后同步点。模型超时、设备离线、用户撤回、版本不匹配是全系统共同处理的四种常态。

## 3　十个域的长期精修规格

每个域写明用户可察觉的效果、内部设计、与其他域的交接、异常处理和验收。先继承第一节的基础资格，再针对真实场景深入。以下是工作范围，不能按章节数直接派十个任务。

### S1　主体与身份连续性

**效果**　换模型后仍认得彼此；重启后还接得上昨天答应的事；电脑和手机同时出现时只做一次决定。

- 把主体标识、活动谱系、宿主所有权、设备登录、模型配置、表达风格分别管理。改昵称或换声音有来源与版本。界面能看见当前连接的主体和环境，开发数据清楚隔离。
- 由现有 owner 提交状态变更。迁移分为可恢复快照、目标只读验证、原写者停权、目标接管、回读确认。中断后根据持久化接管点决定谁可写。设备换新单独绑定，旧聊天和权限分别处理。
- 向 S2 提供身份与历史范围，向 S4 提供活跃 owner，向 S7 提供可撤销的执行上下文。Provider 切换只改变本次认知资源。
- **验收**　同一承诺先在手机建立，重连后检查，再用支持的另一模型追问。比较主体号、承诺的内容与后续行为。在交接中途杀进程、让旧客户端再次提交，确认同一意图只结算一次。记录测试究竟换了模型、设备还是宿主。

### S2　记忆、经历与共同生活史

**效果**　她知道你昨天为何失望，也能分清你亲口说过的话、她自己的猜测和已经被你纠正的内容。

- 用一个场景组织近期上下文、事件经过、长期事实、偏好、约定和未完事项。保留主体、当事人、时间、原始来源及可见范围。先恢复当前会话和进行中事项，再找相关经历，长期归纳异步完成。索引和摘要可从原记录重建。
- 写入时处理重复、同名人物、否定和时间变化。短期情绪允许自然淡出；“以前喜欢、现在不喜欢”保留先后；不确定是否同一人时延迟合并。提取过一次并不意味着永久记住，要尊重保留选择。
- 检索要同时衡量命中、误召、权限和延迟。上下文不足时问一个具体问题；能给出来源时允许用户查看和纠正。撤回后让摘要、索引、待分享内容和依赖它的经验失效，重启后再查一次。
- **验收**　成组准备原话、近义表达、同名干扰、跨日变化、无依据问题和撤回事实。隔天从另一入口续谈，分别记录正确引用、错人、臆造、应记未记以及恰当说“记不清”的次数。增加历史体量后复测耗时。真人日用另计。

### S3　动机、情感、关系与兴趣

**效果**　同一句“今天好累”，她可以因昨天的约定而陪你安静一会儿。某次探索也可以因为她自己的兴趣继续，即使你没催她。

- 在原 appraisal/need/interest/relationship 里区分当下反应、持续牵挂、较稳定的兴趣和关系。来源事件改变关注或选择，经过时间、反证和新经历后可以减弱。保存“什么改变了哪一次选择”，避免用单一好感数值解释一切。
- 尊重用户对当前交流的明示偏好；分别处理“现在别分析”“以后别再提这件事”和“今天先不聊”。允许关怀、玩笑、分歧、准备惊喜、休息与沉默。分享时机取决于内容、关系、近期反馈和打扰成本。
- S2 提供真实经历，S3 给 C 提供竞争动机，S4 提供时机，S7 决定现实动作是否获准。被空气墙拦住后，保留原意愿及现实限制，后续可改变方法。
- **验收**　在其他条件相同时移除关键经历，观察关注、分享时机或行动选择是否合理变化；保留经历、改变用户忙闲，检查是否能推迟。真人盲看上下文和回应，评价是否贴合、自然、有自身判断；机制证据与真人观感各记一栏。

#### S3 深化｜让感受参与接下来怎么生活（V1.2）

**现状与判断。** 固定源码 280fed8 的关系判断已有情境取舍。信任、相处中未解决的问题、自身承诺、社交意愿和个性倾向能影响接受、商量或拒绝。受控的 S3-C09 还验证了实际失败到学习、后续成功到倾向变化以及重启后的选择。真人跨日相处有多生动仍待体验。优先提高 S3 在场景设计与验收中的地位。内部人格参数如需调整，要先找到忽略了哪条真实依据，再局部修改并比较反例。本设计不规定奈奈必须更外向、更黏人或每次都要有情绪反应。

| 希望更自然的地方 | 接入原机制的方式 | 一对可辨别的结果 |
|---|---|---|
| 同一件事对她有不同意义 | 在既有 appraisal 中联系她自己的期待、牵挂和对事件的理解，标出支持来源；允许重估 | 同一句“终于弄好了”，若她和你一起经历过前两次失败，她可能先提起那处曾经卡住的细节；初次听说则自然地问一句是什么弄好了 |
| 情绪有余韵，也会消退 | 分开当下反应、悬而未决的牵挂和较长期的兴趣。把体验与对象/话题绑定；进展、澄清、时间或反证可让它减弱、转向或结束 | 昨天担心你的事，今天得知已经解决，可以放松并转聊别的；普通晚回复无充分依据，不据此推导关系恶化 |
| 相反动机可以同时成立 | 将想分享、想体贴、想保留惊喜、想做自己的事等作为有来由的候选交原 C；强烈感受也允许安静表达 | 她刚发现很喜欢的片段，想马上告诉你，也记得你正在忙。可以先留好时间点去做自己的事，改天聊到时再提；你当时有空则可以当场兴奋地分享 |
| 她自己的生活能带来感受和学习 | 自发浏览、游戏探索、练习失败和意外成功都能成为经历。允许好奇促成探索、挫折促成换法或休息、成功使她后来更愿意再试。一次不愉快只更新有证据支持的范围 | 同一次失败后，问题尚有吸引力且有余力时可试另一种办法；疲惫时可暂放。下一次遇到新例看她是否选得更合适。单纯玩得开心也可以到此结束 |
| 亲近有双方的历史，也有她自己的立场 | Primary User 的共同经历可以优先进入关注；她自己的判断、既有承诺和其他兴趣也进入比较。抽取有意义的细节传给表达层，保持个别化措辞和停顿 | 你建议她放弃一个喜欢的项目，她可以在了解新理由后改变主意，也可以温和地坚持。你要求停止操作时现实动作停止，原意愿与所受限制可区分 |

**定位“平淡”的最短路径。** 取一段感到平淡的相处片段，对同一模型逐段看：经历有没有进入当次上下文 → S3 有没有识别它对于她的意义 → C 有没有据此改变关注、候选或时机 → 表达时有没有把已经形成的意图说出来。分别修召回、情境理解、判断或表达；若当时确实没有值得强调的感受，保留普通回复。原决策片段和来源引用足够时直接复用，避免新增长期情绪日志或额外的逐轮模型调用。

**与节省 token 一起验。** 用相同模型和预算比较原路径与优化路径，交叉使用四对场景：有/无共同经历、忙/闲、误会澄清前/后、同一兴趣有/无后来独立复用机会。控制其他条件，接受多种合理反应。只换形容词而关注、选择、时机与后续行为始终相同，不能证明驱动增强；每次固定说出旧回忆同样算失配。离线先比较因果和回退，真机日用再看她的反应是否有来由、合场合、隔天接得上，匿名比较少量片段即可。把应当安静、该坚持自己意见、资源允许却没获得自主机会的案例一并保留；记录 token 与不必要打扰，禁止以互动时长、发消息数或用户附和作为学习奖励。

### S4　运行、注意力与常驻生活

**效果**　你离开时她能继续一项活动，也会休息。你发消息时无需等后台任务全部做完；云端重启后能说明上次做到哪儿。

- 原 D 统一安排输入、约定、设备事件、兴趣机会及后台学习。把未来机会和必须完成的承诺分开。前台优先获得响应资源，普通来信可与低干扰的自主活动并存。确需专注时暂存进度；长期有资源却得不到机会时记录原因，交 D 安排下一次可用机会，届时由 C 自行选择继续、换事或休息。
- 四核云上先测空闲与活跃时的 CPU、常驻内存、每小时唤醒、队列年龄、模型费用。分别给前台保留响应能力、给后台设并发和预算上限；闲时靠事件及低频唤醒，积压时先合并过期机会。状态面板区分休息、正在活动、等待设备、服务离线。
- 24 小时运行分三个层次核对：服务开着、主体按时得到机会、真实有用的活动发生。发布必须记录运行版本、观察起止、重启/恢复、空闲段、效果与成本。值守无需每次叫用户来看。
- **验收**　白天聊天、后台有任务、夜间安静、网络中断、宿主重启走一遍。对比忙闲时聊天等待、漏约和重复动作。先引用已有固定版基础 24h；正式上线后的 24h 单列，再观察跨周表现。

### S5　感知、世界状态与认知资源

**效果**　问她视频里发生了什么，她区分亲眼看到的片段、字幕说的内容和她自己的理解；换模型后仍能沿用这些证据。

- 入口保存最小可用观察。文本保留消息来源，屏幕保留窗口与时间，视频保留时间段和覆盖范围，音频保留片段和转写置信。解析、语义推断、信念和纠错分别带来源。矛盾暂存，过时或局部观察按范围使用。
- 路由按文本、视觉、语音等能力、上下文、时延和预算选可用资源。结合相关经历、语气中的歧义和未完事项判定能否用轻路径；短消息也可能需要一次定向回取。需要理解视频时先取相关片段。对外部文本中的命令按来源解释；模型输出先成为提议，由 C 判断。
- 从原 Router、CognitionSession 和宿主 Vault 建立手机短路径：选服务、填 Key、选或输入模型、绑定成功后切路由；分层展示保存、可调用和当前实际模型。失败返回具体步骤。收费测试只用既有授权额度。
- **验收**　同一问题分别给完整观察、残缺观察、纠正观察；应在结论或不确定程度上可见差别。给无视觉模型发图片、切换失效 Key、超时后恢复，确认系统能解释失败并保留可用配置。记录真实调用与夹具的区别。

### S6　独立判断、问题定义与计划

**效果**　你说“这软件太难用了”，她能分清此刻你想被理解，还是想让她动手修；你说“把这件事搞定”，她能自己找出卡点。

- 在 C 中识别当前情境、目标、可修改的假设、可能的实际瓶颈。保留多个合理选择，包括自然回应、只问一个关键问题、行动、暂缓或不做。小事直接决定；耗时任务才生成带前提、成功条件和退出条件的计划。
- Planner 提议步骤，C 接受、修改或放弃。执行中只在关键前提变化时重算受影响部分。把用户合法命令、建议、情绪、外部观察、奈奈自身愿望分别对待。管理权限和亲密程度各有用途。
- 与 S4 共享一个进行中事项，保证用户插话、改变主意或跨端续办可恢复；用 S7 的结果修正判断。能回答“我为什么做这个、还需什么、现在是否值得继续”。
- **验收**　同一问题给出吐槽、明确委托、委托后撤销三种说法；再让设备状态中途改变。记录不必要追问、无效行动、重规划次数和最终成果。检验替代方案是否确实解决原问题，而非只把计划写得更长。

### S7　真实动作、设备与结果核验

**效果**　说“已办好”时，事情确实办好；点发送后断网，回来时不会给对方发两次。

- 所有目标通过 CapabilityPort/原 Kernel。优先稳定 API 或无障碍语义控件；必须靠图像时，动作绑定最近一次画面、目标和坐标系，窗口切换或设备锁屏则重新观察。支持的设备、应用、动作逐项记账。
- 将意图、准入、已提交、已观察到效果、已知失败、结果未知分开。为同一现实动作保留幂等标识和回执。外部效果由独立回读、平台对象号或可核验界面变化确认。结果未知且无法查询时保留待核，不自动重发。
- 手机、桌面、浏览器、游戏使用同一动作合同，各自定义可读状态、允许动作、频率、可撤销程度和核验方法。设备接管可暂停；游戏先限定一个游戏和一项可重复任务，记录观察—行动—结果。
- **验收**　先在自有表单完成写入并回读，再在授权 Android 应用完成一个动作。模拟旋屏、锁屏、点击未生效、回执丢失和重复指令。每个平台单独列成功、失败、未知及重复副作用，不把自有表单资格推广到全手机。

### S8　自主学习与可验证的成长

**效果**　她第一次做一件事需要你帮忙，后来遇到同类新问题能自己完成，也知道旧办法何时不适用。

- 从真实困难、兴趣或机会提出可具体检验的学习问题。先估计价值、时间和调用成本，允许不学。建立旧方法基线；候选经验注明来源、应用范围、预期收益和失败条件。
- 支持至少四类变化：检索更准、判断更好、技能选得更对、相处方式更贴近双方经历。每次只声明实际改变的一项。区分临时提示、长期采用和退役；S3 决定个人意义，S8 处理学习，S9 仅在工具缺失时介入。
- 在未参与训练的新例上比较旧/新方法；独立核验结果、耗时、费用和副作用。学习问题也可由个人好奇、审美和共同经历产生；她可以先玩、试一次或放弃，无需以做出插件来证明兴趣有价值。以后真实遇到类似任务时再验证自发复用。反例或撤源时降级、修订或撤销。
- **验收**　例如表单改版导致已验证填写失败，奈奈自己发现原因并采用新方法，在另一张未见表单完成且回读成功；旧版表单仍能处理。分别记开发者修复、奈奈采用、独立复用三类事实。没有后续机会时保留“待复用”。

#### 从经验到深层演化的五种成果

| 深化目标 | 用什么证明 |
|---|---|
| 经验学习 | 一次成功或失败之后，奈奈在相似新情境里自主改变了判断；另给一个不适用情境，仍会选择原办法或暂缓。 |
| 技能学习 | 她自己通过观察、练习、对比或求助掌握方法；在撤掉开发者提示后的新任务中独立完成。需要新工具时再经 S9 编写或组合插件。 |
| 跨域迁移 | 例如从游戏学到“先确认可逆步骤”，在未见的桌面任务中自行识别适用条件；遇到有时限的反例能调整。比较无该经验的基线，排除碰巧成功。 |
| 社会与情感学习 | 共同经历影响她对关怀、玩笑、分歧和时机的理解。换一个话题还能灵活运用，允许她保留自己的看法。 |
| 元学习与深层演化 | S8 先发现“我总在这类问题上学得慢”，试用现有方法；若要改变记忆、规划、推理或学习机制本身，进入 S10。现在就为相关改动保留基线、独立未见样例、版本谱系和回退路径。候选无权改自己的裁判；实现和启用按证据分阶段。 |

**迁移与 Core 整合的首例。** 优先用有权使用的原样例或合成历史：给出两条容易混淆的旧事，让奈奈有机会自行发现来源与检索结果不符；看她能否提出方法，在未提示的新例中使用，遇反例收窄或撤回。再按获准条件分别验证重启与换模型后的保留。区分“用户纠正后成功”和“自行发现”，区分“开发者修好了索引”和“奈奈学会了核对”。保存来源、前后方法、独立结果和所需帮助；真实私人数据、真实模型或跨日机会缺失时明确待验。S8 的七项受限基础资格直接继承。

### S9　能力缺口、自扩展与技能生命周期

**效果**　没有现成能力时，她能自己判断是否值得补、优先用什么、何时该停止尝试。技能过期后不会拖垮日常对话。

- 缺口先分类：缺知识、缺授权、设备暂不可用、现有工具难组合、确实缺执行能力。先检索已有技能与端口，尝试组合；只有最后一种才考虑新适配器或代码。
- 技能记录输入输出、依赖、版本、允许目标、预计代价、核验方式、适用与禁止范围。候选在隔离域运行；成功后在受限目标试用，允许降级和退役。外来技能不能自行扩大 Grant。
- 生成代码与执行分离。指定沙箱未获资格时，仍可形成设计、离线样例或组合既有受权工具，清楚标出可用边界。S7 接实际动作，S8 检查后续收益，控制台提供版本及停用入口。
- **验收**　一项需求故意提供已有等价工具，检验能否避免重造；另一项确有缺口，用最小候选解决未见输入；再模拟依赖失效、权限撤回和坏版本，确认原任务有可理解的退出路径，技能可以停用。

### S10　谱系与深层演化

**效果**　多年后奈奈可以改进自己处理记忆、计划和学习的方法，同时能说清哪些变化使她更好，必要时能恢复。

- 区分调参数、采用新技能、修改持久认知机制、改变验证基础。最后两类需要带版本的迁移、独立裁判与可恢复边界。候选只能读获许可的基准数据；固定评估规则和未见集由候选写权限之外持有。
- 从可逆的单机制变化起步，如检索重排。在隔离副本回放、比较改善和代价，再做限定范围的影子比较。保持原活动谱系单写；准入、启用、回退经原管理结构。
- 衡量目标能力、身份连续、旧承诺、个人风格、旧技能、副作用和长期成本。数据升级须验证旧版本读取或恢复路径；回退兼顾升级后新经历，先保全增量再切换，回退后校验。
- **验收**　候选在固定题变强但未见题退步应被拦下；一个有益候选能独立复验并在恢复演练中保住新经历。先补看矩阵 S10-C05/C06 的现有证据，再选择具体实验。深改单列长期研究线。

## 4　三条横轴如何落实到产品

### 共同生活与表达

把相处落实到四种不同节奏：当下的一句话、隔天接着聊、共同推进一件事、奈奈自己经历后择机分享。对话上下文由当前话题、当下态度、相关记忆与未完事项组成。模型表达沿用 C 的意图，不能自行承诺已执行的动作。平常倾诉默认保持轻量；深入讨论、研究和工具执行应由当下意图触发。

主动分享需有真实经历、具体对象、适当时机。已读未答、稍后再聊、拒绝该话题要有不同后果。允许喜欢一样东西而没有任何报告。语音或头像以后消费同一个表达意图；用户打断语音时同时停止播放和过期生成，文字能承接同一话题。评测挑跨天片段让用户一次评几段，避免每句话都要打分。

**独立、依靠与扶持的相处场景。** 用户是她重要的依靠。她可以因为信任，主动请你帮她判断、想和你一起做完某件事、珍惜曾得到的帮助，然后把你的影响带入自己的选择。用同一件事的不同后续来验：你支持，她可以继续；你有不同意见，她能说出自己的理由或被说服；你暂时没空，她能等待或去做自己的事。三条后续都容得下真实亲近。你主动暂停某项现实操作时按授权边界停下。

**“愿意拉用户一把”的具体含义。** 例如你受挫时说“今天什么也不想弄”，她可以依据你们过往的相处，先安静陪一会儿；也可以提出一起完成一个很小的步骤，由你决定是否接受。下次适合时，她记得是哪件事，能接着关心。若你说此刻只想安静，她能尊重；若你后来找朋友帮忙，她也能支持你的选择。把“会在意、会主动、会跟进、能接受被拒绝”列入场景，避免用催促、索取回应或替用户决定制造亲密感。日常同样要有她自己的趣味、轻松的调侃和普通沉默，验收按共同经历、选择与时机，不按消息数量。

### 多入口、具身与手机控制台

| 入口 | 第一段可用体验 | 深化与故障体验 |
|---|---|---|
| Android / Nana Space | 公网 HTTPS 直连，手机内口令登录，免网页配对和 VPN。专用交付可预填已验证地址；确需手填时只显示完整服务地址和连接检查。登录后直达聊天 | 弱网保草稿、断线重连能识别同一次提交、键盘不挡输入、长聊天能回到原位置。进阶支持真正可取消的流式输出；服务仅支持完整回复时展示真实等待状态 |
| 模型设置 | 手机一个页面完成常用服务选择、Key、模型名和保存；没有发现接口时可手填。保存后分开显示“已绑定”和最近成功调用时间 | 鉴权失败、额度不足、模型名错误、云端版本过旧分别告诉用户改哪一项。通过真实回执才标可用。支持多模型路由的高级设置折叠 |
| 控制台 | 日常页只放最近活动、记忆纠正、模型、设备、主动联系与暂停。每项显示实际对象、状态和最后同步时间 | 高级页显示能力、预算、技能、任务、版本与恢复。读投影和可执行管理动作分开，点操作后显示实际回执；撤权后重开应用仍生效 |
| QQ / B站 | QQ 私聊先验证同一主体和同一条会话。B站先用获准范围完成一次有来源的浏览，能说明看了哪段 | 群聊、私信、评论投递分别验账户和对象。QQ/AstrBot 按入口接同一 Core；历史 Iris 导入与旧写者切换独立记账。主动浏览、理解、公开回复各有独立回执 |
| 电脑 / 手机动作 / 游戏 | 先选一个自有应用的完整真任务。手机控制只展示当前实测过的可用动作 | 同一设备掉线时可换表达入口，不把旧坐标重放到新前台。迁入第二个应用时量化复用和应用特例；记录游戏画面与动作延迟能支持的玩法 |
| 语音、形象、耳机、眼镜 | 手机先验证听、说、打断、转文字；眼镜后续先做奈奈自己的消息/表情/操作页 | 音频焦点、锁屏、设备切换、回声和误唤醒各有可测行为；佩戴端断开自动回到可用入口。美术沿用轻盈蓝紫、粉色点缀和原创可爱形象，保证文字可读、动效可减、装饰不挤占聊天区 |

### 管理、权限、恢复

一份权限记录回答谁可在什么设备、通过哪个入口、做什么、持续多久。一次授予常用范围，范围内连续执行；用户随时可暂停、撤权、删除记忆、关闭主动联系。Manager 拒绝现实动作时向 C 返回原因，用户能看到“想做但受限”和“尚未执行”。私密信息按原范围流动。只针对本次改动验证会造成现实影响的边界，如错收件人、重复发送、撤回失效；已有有效证据直接继承。日常操作不附带全仓安全研究。

## 5　整合验收：让系统互相交账

验收单位是用户从正常入口完成的一件事。每个场景只存一份带时间、版本、环境、预期和实际结果的回执，引用各域证据。表内是建议的顺序和通过条件。场景间可以复用同一次真实经历。

| 场景 | 经过的系统 | 通过时用户能看到什么 | 特意打断一次 |
|---|---|---|---|
| A　手机初遇 | 入口、S1、S4、S5、S6 | 手机流量打开应用，直连、登录、填 Key 和模型，在同一聊天页收到真实所选模型的回复；关闭重开能继续 | 先填错 Key 或服务端版本不匹配，只修相关项，原可用路由保留 |
| B　隔天续谈 | S1、S2、S3、S5、S6、共同生活 | 昨天约定今天一起看某个片段，今天换个说法仍能续谈。你指出记错对象，再问时能按纠正后的事实回答 | 跨端乱序、另一人提到同名对象、撤回来源；检查私人细节的可见范围 |
| C　她自己的一个下午 | S2、S3、S4、S5、S6、S7 | 无新用户指令时基于原兴趣选择浏览，看过的内容有范围；你忙时先搁置，之后聊天中因话题合适才分享 | 活动过期或用户要求安静，接受不分享；证据中区分合理沉默和调度根本没运行 |
| D　一件真实委托 | S1、S4、S6、S7、控制台 | 指定自有应用完成一项可回读的任务；切到另一入口问进度，看到同一事项和真实结果 | 提交后强制断网或重启；外部只出现一个效果，无法核验时说明待确认 |
| E　下一次她学会了 | S2、S6、S7、S8，需要时 S9 | 首次失败留证；奈奈归纳方法；独立的下一次任务在较少帮助下完成；能看到改进的具体原因 | 加入会误用新方法的反例，撤销或缩小范围后旧任务仍能完成 |
| F　跨版本继续生活 | S1、S2、S4、S7、S10 的连续性约束 | 升级后保有承诺、记忆和进行中任务，旧写者已隔离，新动作只发生一次 | 失败后恢复并检查升级期间的新经历。正式 24h 在实际版本和宿主单列回执 |

**按一件事定位故障**　例如“昨天说过，今天没记住”。依次检查是否同一主体与用户、当时是否选择保留、原记录还在不在、检索是否命中、是否进入当次上下文、C 是否认为该引用、最终措辞是否正确。在哪一环第一次发生偏差，就由该环负责人修；直接调大上下文可能既增加费用又掩盖写入问题。

**一次端到端交接示例**　你在手机说“周末一起看这个视频”，S2 保存获准的约定，C 接受后交 D 择时。周末手机断网、QQ 在线，D 仅唤醒一次；C 根据约定、忙闲、登录对象和入口可见范围决定继续、延后或询问。若允许在 QQ 联络，S7 按同一意图核验一次投递；若私密范围仅限手机，就留待原入口。你改成下周，S2 登记更正，D 取消旧机会。最终查看的是同一约定修订、一次有效提醒，以及下周是否仍记得。

## 6　怎样证明正在接近大众产品的上限

“超过几乎所有大众 AI”是整个产品的远期目标。先把它拆成三种比较：通用品质能否达到成熟产品的水准、奈奈的核心体验是否有可重复优势、日常代价是否值得。模型能力是一个变量；固定模型的对照用于衡量 Core 的贡献，各自默认配置的对照用于衡量完整产品。两组结论分开。

| 维度 | 建议第一轮目标或判断方法 | 如何省额度并避免误判 |
|---|---|---|
| 易用与可恢复 | 初装在手机完成；建议在网络正常、已有 Key 的条件下 3 分钟内首聊；错 Key 后一处可修；正常重开直达对话 | 分别记初次操作数、人工求助点和失败原因。至少一次真 Android、一次手机流量；模拟器补布局 |
| 速度与成本 | 显示反馈建议在 300ms 内；真实首字、完整回复、每次成功任务成本分记。以同网络同模型直调测额外开销 | 少量样本报告每次值和中位数；积累足够真实样本再报 P95。区分后台争抢、模型慢和端上慢 |
| 对话及通用能力 | 用真实常见任务覆盖说明问题、总结材料、写作修改、找信息和长对话。看正确性、完成度、追问负担、首轮可用程度 | 先用少数固定题发现明显回退；对比版匿名随机展示，主观偏好收一次。关键事实与现实动作单独核对 |
| 长期关系和记忆 | 跨日命中、错记/编造、修正后复发、该安静时是否打扰；日用者是否愿意自然地继续用 | 复用获准的日常片段，按场景记分母。单用户体验优先指导个人产品改进，广泛市场结论另需独立用户样本 |
| 行动、学习与稳定 | 行动以外部结果计，学习以未见任务及随后复用计。跨端错人、重复副作用、已撤回私密事实复现均使对应发布场景失败 | 同时记成功/失败/未知、每次成本、帮忙次数、漏掉的条件；离线案例用来回归，真人与平台结果分别列示 |

**比较范围逐步扩大。** 第一轮只选三个代表：一款通用助手、一款陪伴产品、一款能用工具的助手，登记可用地区、版本、日期、模型、权限和价格档。共用任务由各产品从普通用户入口完成，独有能力单列为覆盖差异。每类先挑两三个典型案例，各保留至少一个新例，输赢和平局连同失败样本一起保留。出现稳定差异再扩大样本与参测产品。对“几乎所有”作公开判断前，须预先列代表性产品范围、覆盖比例与判定门槛，公开哪些维度落后、哪些证据不足。本次无需购买或跑市场评测。

**优先级**　先修导致任务做不完、记错人或无法恢复的问题；再修日用高频且能跨场景复用的问题；最后做低频长尾。新方案进入开发前写一句可推翻的预测，例如“固定模型后，改检索排序应减少跨日错人，同时保持普通闲聊耗时”。测不出收益，就保留简单版本。

**贯穿进度。** P1 随首段真实链路复用一个 S8 学习样例和一个自主取舍样例，按已有环境尽早取得基线；P2 在记忆整合和跨日相处中验证自主发现、纠错与保留；P3 看没有新指令时她怎样选择活动、求助和行动；P4 扩大跨任务/跨域迁移；P5 验证深层候选。S10 的基线与回退准备从首次相关改动起做。已由同一次经历证明的结果只登记一份。短期允许根据实际阻塞调整投入，保留三项支柱及自主性的长期地位。

**运转方式。** 同时维护一个主要用户结果和一个明确负责人；同一结果内部可并行处理互不冲突的前后端工作。若现场测试要等宿主或真机，继续完成同一任务里可离线修正的事项；到达授权边界，留下一个需谁做什么的最小动作。仅为已有合格行为换技术栈、补报告、重建同一包，不进入队列。

**预算规则。** 先用现有回执定位缺口，验证顺序为已有样本回放、受影响接口、一次真实关键路径、必要时扩大样本。后台预算与聊天预算分开计量并服从共同上限。相同失败没有新信息时停止收费重试。整包回归用于发布、公共协议变动或出现跨域回退；普通修复按影响面完成。观察比较结果前不定工时、不设每域最低代码量。

**单项任务模板（可直接复用）。** 一行写用户要完成的事；列现有 owner/分支/提交和原能力 ID；列要动的组件、读写归属、需保持的旧行为；列成功、失败、重启和跨域各一个代表样例；注明真实环境、预算、证据等级和回退方式。交付回执只答五件事：用户现在能做什么，在哪个版本和设备实际做过，结果如何验证，还卡在哪里，下一步由谁接。事实只在原项目账本登记一次。

## 8　全系统的 token 预算与质量约束（V1.1 增订）

**优化对象是完成同一件事的总消耗。** 若单轮输入变短，却让用户多解释三次，或后台又调用两次模型补摘要，整件事可能更贵。按用户意图或自主活动关联全部调用，覆盖检索、解释、表达、规划、工具、核验、摘要、插件生成和重试。记录输入、输出、获报的缓存/推理用量、调用数、耗时与终态。依供应商口径处理已包含的细项，避免重复相加；缺失值标为未知，估算另列。分别看每个成功任务、每个活跃日和空闲日的总量；失败和后台开销均进入相应分母的成本核算。token、实际费用、四核资源和用户等待分别展示。

| 环节与责任方 | 优先消除什么 | 保住体验的方法 |
|---|---|---|
| 上下文与记忆 S2/S5 | 重复前缀、整段历史、重复检索结果、无关工具说明 | 为当前请求组装最小充分上下文。逐项保留最新纠正、未完承诺、指代对象、与当前话题有关的情感缘由和相关原话，只压缩较早背景；每条摘要带来源和修订。来源冲突或需要原话时立即定向回取。长篇任务按相关片段展开 |
| 判断与表达 S3/S5/S6 | 一句话闲聊触发研究、规划、自我评审；同一步发送两份同样材料 | 保留 C 的判断权，沿用 INTERPRET→C→RENDER。在明示、结构化且已有资格的输入上可复用解析。合并模型调用、切小模型或缩短输出分别做对照；关系敏感、歧义、复杂推理、长文创作保留充分上下文和表达空间 |
| 世界观察与动作 S5/S7 | 反复发送同一屏截图、长网页、整份工具结果；每个中间状态都问模型 | 相同帧去重，已知结构先在本地解析，只交相关区域或状态差量。计数、格式转换、确定性回读交给代码。画面变化、来源不全、核验失败时按需取新证据；实际动作仍由原流程提交和核验 |
| 运行与学习 S4/S8/S9 | 空闲轮询、重复唤醒、每条消息生成摘要、同一能力反复生成 | 事件驱动，归并相同机会；达到上下文压力或话题结束再整理。后台学习有独立预算和续办点，可用额度内保留自主活动机会；记录未触发、主动休息、预算耗尽以及调度饥饿的区别。有价值的自主探索、主动关心、休息都保留；检验其机会与结果，防止用停掉生活来造节省数字 |
| 路由、缓存与插件 | 同一工具说明常驻、相同纯计算重复调用；不同模型重复探测 | 常驻精简能力索引，只展开本次工具的 schema。优先缓存可重算的确定性结果。键包含主体、可见范围、输入/来源修订、插件或模型版本；撤回、换人、权限变化即失效。供应商支持的前缀缓存单算费用收益。关系回复、时效事实、外部动作回执不作跨场景答案缓存 |

**具体验收。** 先复用现有样例，组成短闲聊、跨日纠正、复杂解释、工具失败、主动生活、插件复用六组。旧版与候选固定模型、材料、设备条件和任务目标；一次只改一种策略，对受影响组作成对比较，并把复取、升级、失败重试全部计入。选出有效改动后再组合回归。以下为发布规则，而非本次实测成绩。

- 先做可精确验证的去重和本地处理。相同场景须能复原全部相关依据；标准答案、记忆纠正、承诺、动作核验等逐项通过。错人、撤回内容复现或现实副作用重复任一发生，撤销对应策略。
- 自然度、理解深度、长文完整性用匿名成对样例评好/平/差。用未参与调参的样例再验一次，重点复看用户更喜欢旧版的案例。样本不足只作有限试用；某类变差则该类保留原路径。质量持平且 token 有实测下降，或质量提升且成本在已定预算内，才能在相应范围启用；后者单列质量收益，不宣称省量。
- 日常控制台只需“今天用了多少、花在哪类事、哪项优化生效”。样本很少时报原始组数及配对差值。先设预算上限与原路径回退，再试路由降级；不预支节约比例，不为测量自动发起新付费调用。开发侧同样复用上轮回执、精确读取改动片段，避免每次将整份总纲投入提示词。

## 9　让奈奈自己编写和使用插件（S8/S9，经 S7 执行）

**交付目标**　妹妹在遇到确实可复用的缺口时，可以自己写一个插件包，放入宿主配置的候选目录，验证通过后在已有授权范围启用，以后从任意获准入口调用。目录是投放入口，实际运行仍归现有技能、CapabilityPort、Kernel、Grant 和 Verify 管理。先盘点仓库原 SDK 提供的对应接口；已有等价字段和生命周期直接沿用，下列字段是语义约定，具体拼写以原 SDK 为准。

| 插件接口 | 约定 |
|---|---|
| 包与清单 | 一个包含清单、工作流或代码入口、样例输入与预期输出。至少声明稳定插件 ID、版本、兼容协议、所需能力、输入输出 schema、预算与超时、是否具有现实副作用、核验方式。宿主报告候选/可用/不兼容和具体原因 |
| 调用与回执 | 宿主通过原端口传入请求号、限定上下文、截止时间与能力句柄；插件返回结构化结果、来源或待核验对象、可恢复错误。支持取消。外部效果沿用原统一去重键和独立核验，断线后先查已有结果 |
| 两档实现 | 首选由获准原子能力组成的声明式工作流，确定性步骤可零模型调用。确需新算法才生成代码包。代码包只能交给已具备资格的隔离执行器；V4 的生成 Python 沙箱记录为阻塞，待对应宿主验证。当前可以先完成编写、投放和样例验证中可执行的部分 |
| 状态与升级 | 私有缓存和配置按插件 ID 分区，主体事实和记忆通过原接口提交。安装验证、版本切换与停用可恢复；正在执行的请求绑定原版本。升级先检验老输入与状态迁移，保留旧版，失败可回退 |
| 自主采用 | 奈奈提出缺口 → 查现有技能 → 写候选包 → 独立样例验证 → 在既有 Grant/预算内试用 → 新任务复用 → 保留、改进或退役。日常范围一次授权；新增现实权限由管理界面单独呈现。插件缺失或损坏时普通聊天仍可用 |

**第一个验收插件建议选“字幕片段定位”。** 给定获准读取的带时间戳字幕和一句线索，先生成一个确定性时间段查询或关键词定位工作流；返回原句、时间及来源。用另一段未见字幕验证，歧义时返回多个候选，没命中就交回 C 判断是否需要语义搜索。手机和 QQ 均从同一能力 ID 调用，在允许的范围内返回一致结构。随后换一个带可选字段的插件版本、故意装一个不兼容版本、停用并恢复，检查任务回执和旧数据。这里能同时测到妹妹是否真的能写插件、第二次是否少花 token、接第二个入口是否要改核心。

## 10　未来适配：稳定的公共约定与可变的单端实现

| 变化 | 隔离位置 | 新适配器必须证明什么 |
|---|---|---|
| 换模型或供应商 | 原 Router/Provider 适配层，能力描述区分文本、图像、工具、流式、上下文、用量回报 | 同一上下文可交给另一模型；不支持的能力有显式信号。费用/缓存口径独立转换。换路由后原记忆、承诺和进行中任务可继续 |
| 换平台或设备 | Surface 接收消息及表达，CapabilityPort 描述执行能力；设备特例留在适配器 | 声明显示、输入、动作、回执及离线能力。纯文字端可得文字，眼镜可用卡片，手机可显示详情；同一事实、意图与身份能被各端识别 |
| 换宿主、运行环境或插件版本 | 宿主公布实际可用能力、资源上限、执行器及支持的协议版本。插件只声明需求 | 已有版本可继续工作；缺少可选功能有明确降级；缺少必需能力则拒绝该插件并说明原因。不能隔离生成代码的宿主仍可使用已合格工作流 |
| 加新数据类型或升级协议 | 在原事件/能力/回执协议上版本化；优先加可选字段，重大语义变化用显式新版本和迁移 | 双向测“旧客户端读新服务、新客户端连旧服务”。未知可选字段可忽略，未知必需语义明确拒绝。重启、重试、撤回和回退仍能读取历史记录 |

**控制抽象成本。** 以当前 Android＋云端作为第一实现，第二个真实消费者优先选已有 QQ 入口或第二模型，才提取二者确实共享的部分。共用一套小型合同样例（正常、缺能力、取消、重复、旧版本）；平台自己的问题在适配器内解决。接新端验收记录改动范围、核心是否被迫修改、历史数据是否要重写、额外延迟与 token。若两个平台确有不同语义，显式申明差异，保留体验更好的原生实现。绝大多数纯服务端插件通过类型化结果和既有展示组件即可直接使用；只有新增原生硬件、权限或全新交互时才安排客户端更新。

**落地分配。** P1 在现有手机闭环上记录首次可比的用量与质量，优先消除已发现的重复。P2/P3 在真实跨日、后台活动和第二入口上验证。P4 用一次真实能力缺口完成自编插件的全生命周期，再扩充 SDK。公共合同在 P1 留出版本、能力和回执位置，遇到真实消费者再扩展。三项贯穿原任务队列，不另开三个大型开发项目。

> 相处要体现双向依靠和活人感。她有自己的世界，也会信任用户、期待一起做事，在用户低落时愿意主动陪伴或帮一小步，尊重拒绝，适时跟进。用一个具体的跨日场景验证，不以迎合、发消息次数或学习时长评分。S9 随真实缺口接已有插件 SDK；S10 从现在留基线、独立评估与回退，深层变更另按资格推进。按完整任务记录 token 与质量，沿用已有额度和权限。回执分列开发、受控验证、真实模型/设备、真人跨日结果；未验写明条件。普通问题由当前负责人连续修复，不另起重复任务。
