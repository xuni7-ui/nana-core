The existing three-frame storyboard projection now rereads original frame memories and the original source immediately before returning. Controlled source and individual-frame withdrawals during the final read both fail closed. This is a pre-return recheck, not an atomic lock across later consumers. C's original video lineage, original private-source and A synthetic-binding/stream tests passed 32 tests in 17.28 seconds. One 100-call same-machine synthetic sample measured old projection median/P95 0.2209/0.3695 ms and new 0.3221/0.4506 ms; process CPU was 0.02519/0.03393 s respectively. These are single runs, not a production benchmark, and no additional platform/model calls were made.

`public_video_cache_handle` and `with_current_public_video` are a **candidate handoff**, not an installed Bilibili consumer or a new authority. They read the original MemoryService and MEDIA_OBSERVATION record, require current PUBLIC direct VIDEO evidence for the original runtime entity and permitted scope, match its original byte digest to an existing `MediaCache` handle, and recheck the original evidence after a trusted synchronous materialized candidate operation. The operation must independently verify cached bytes against the handle hash. An awaitable or lazy iterator, mismatched source ID/digest, private or wrong-entity evidence, missing cache mapping or withdrawn source is rejected. The caller must run this only after the original C/Manager/Grant/Kernel decides to observe; the wrapper cannot prevent arbitrary effects inside a trusted callback.

`tools/nanalink_b_video_source_qualification.py --b-source <archive-of-bbc3ba7>` verifies the exact hashes of B's two local modules **before executing either**. On an isolated generated 2-second video, original PerceptionService and the original Store produced synthetic PUBLIC evidence; the C gate selected its cache handle and the pinned B decoder returned original PTS 0.5/0.75/1.0/1.25. A second decode deliberately withdrew the original source during the operation while the cache callback incorrectly remained true: the wrapper returned no candidate. A tampered B input was rejected before execution. The local technical codec processor ran, with zero platform requests, paid model calls or external sends. In one 100-call sample, the C gate median/P95 was 0.1979/0.3585 ms, CPU 0.02259 s, process peak RSS 39668 KiB (excluding FFmpeg child RSS); this does not measure video decoding, real tokens or production cost.

The source gate currently covers only existing original **PUBLIC direct VIDEO observations**. It does not establish Bilibili platform/account attribution, obtain a Bilibili video file, promote a storyboard sample to full-video evidence, permit PERSONAL media, persist B's frames or connect B's candidate to S5. The original bounded PerceptionService path is limited to 16 MiB and 30 seconds; B's wider/long-video prototype needs an A-owned source/authorization contract and a real consumer. B is responsible for its visual algorithm, A for original S5/C/S2/S8, and C for platform source/byte and withdrawal linkage. Real platform accounts, device, production, model quality and billing remain unqualified. Revert the C `video_handoff.py` changes and remove the C test/tool to roll back this candidate; no schema migration.
