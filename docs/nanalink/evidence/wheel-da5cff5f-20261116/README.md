# NanaLink fixed-source wheel qualification

C-owned development qualification, source `da5cff5f37d4db200547834e33b49def7e2ffebc`; this source integrates A `35740e7f2f518b9b2607bbd952759aa80683cf4c`. Exact source CI [43852708219](https://github.com/xuni7-ui/nana-core/actions/runs/43852708219) passed. This is not A's final matched Core/BFF/Web/Android release.

A clean `git archive` of the fixed source was built twice sequentially with Python 3.12, pip 25.0.1, setuptools 84.0.0, wheel 0.46.3, `SOURCE_DATE_EPOCH=1794826334`, `--no-index --no-deps --no-build-isolation`. Both outputs were byte-identical: `nana_core_offline-0.1.0-py3-none-any.whl`, 990880 bytes, SHA-256 `a5f3efbce00e0abd811567f3cbdd5711080ea647eff7e311fa2aad9a8a8c9ccd`. This demonstrates repeatability in this prepared environment, not across arbitrary build hosts.

The wheel was installed into an isolated target using `--no-index --no-deps`. All 310 Python files in `src/nana_core` matched the fixed Git archive byte-for-byte; the installed OneBot and official adapters were imported from that target rather than the checkout. From `/tmp`, the installed NanaLink entry point validated the archived example configuration with `--check`, reporting `NANALINK_CONFIG_VALID; no account or network accessed`. Required dependencies were supplied by the already-prepared virtual environment: this does not establish a complete dependency wheelhouse or a production installation.

The pinned old-reader synthetic video lineage tool was also run from the fixed source archive against old Core `cfd11be158a3f0fa36abf93f42d5e4fde1f55bf0`: subject identity and dependency matched before and after parent withdrawal; withdrawn video/frame were unreadable to the old reader, with `user_version` 13 before and after. This is a temporary owned Store test, not arbitrary historical data, a full action replay, private provenance old-reader compatibility, or production rollback. The previously documented requirement to withdraw unsupported private provenance with a current reader before rollback remains.

The two wheel artifacts and isolated installation in this environment are under `/workspace/work/nanalink-qual-da5/`; paths are local evidence only and not a distribution URL. Real platform accounts, paid models, Android device, production, and the combined matched release are not qualified by this run.

A synthetic benchmark on the same archive accepted and dispatched 2000 events and detected 2000 duplicates in 0.1573 s wall/0.1573 s process CPU; peak RSS was 38228 KiB including the Python process and the benchmark’s 8 MiB media cache. It used queue capacity 64, per-account limit 16, dedupe 512, zero network/model/social sends; 8 MiB identical media was reused. A separate installed-wheel run submitted 2000 synthetic events in batches of 16 across two accounts, measuring queue peak 16, median enqueue-to-handler 1.1618 ms, P95 2.0439 ms, process CPU 0.2571 s and peak RSS 26572 KiB. These measurements include the stated harness and are not real platform latency, model token usage, effective cognition cost or long-running stability. No real provider token or cost was measured.
