# NanaLink media read withdrawal safe point

A baseline `90a31b6d10118061c55bf7d3821920b22713463c`; C-owned cache increment. The bounded cache checked the original source before opening a file, but a source withdrawn during the filesystem read could still have its bytes returned. A controlled validator that becomes unavailable after the initial check reproduced the gap. `MediaCache.read` now checks the same source again after the read and raises `MEDIA_SOURCE_RETIRED` before returning bytes if it is no longer current. This does not add a grant, accept private QQ media into the public cache, or modify original C selection/Manager/Kernel. A withdrawal immediately after the final check remains subject to the consumer's own admission/dispatch checks; this is not an atomic cross-process read-and-send guarantee.
