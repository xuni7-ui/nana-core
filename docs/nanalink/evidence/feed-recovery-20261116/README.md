# NanaLink RSS/Atom bounded HTTP and reconnect

A baseline `90a31b6d10118061c55bf7d3821920b22713463c`; C owns this adapter increment. The existing RSS/Atom adapter could parse an incomplete response because `StreamReader.read(n)` is not a read-to-EOF operation. It also stored ETag/Last-Modified before parsing; a malformed response could therefore poison the next conditional request. Separately, disconnect cleared already parsed but not yet delivered entries while the deduplication and validators survived, so reconnect could lose them.

The adapter now reads response chunks through EOF within its existing byte and timeout bounds, stages HTTP validators and commits them only after parsing succeeds, and preserves the bounded pending list across reconnect of the same instance. Existing delivered IDs stay deduplicated. No new platform requests, model calls, Store, permissions or sending are introduced. Revert `src/nana_core/nanalink/feed.py` and its matching test to restore the previous behavior.

The owned loopback HTTP fixture delivered a body in two delayed chunks, first supplied malformed XML with a different validator, then supplied an oversized response. Before the fix, the chunked input failed as incomplete; after the fix the complete event was read and the malformed/oversized validators did not replace the last successfully parsed validator. A separate same-instance disconnect fixture failed before the fix and now retains the undelivered second item without replaying the first. Related adapter, transport and original-Core bridge suite: 27 passed in 2.44 seconds. These fixtures use synthetic content only; they do not prove recovery across process loss or retention after the remote feed removes an entry, real provider operation, or production deployment.

The existing byte-level DTD check also accepted a UTF-16 DTD because of interleaved zero bytes. A synthetic UTF-16 entity fixture reproduced it; the check now normalizes those encoding zeros before scanning markup, and a normal UTF-16 feed remains readable. The combined targeted suite then passed 28 tests in 2.35 seconds. The conservative DTD check remains a rejection policy, not a general XML sanitizer.
