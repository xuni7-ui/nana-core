## What now works

One original C SubjectLoop can consider an actual owned application opportunity,
form an intention, and let original F/Kernel perform an inspect/prepare/apply plan.
The application genuinely changes its own state and document files. Another
read-only channel plus direct persisted-state/file inspection verifies effects.
Task quality is then judged separately from physical effect success.

Verified bad task outcomes enter the existing Experience path. C can REFLECT and
G can select/evaluate a different finite method. Retrying the original real task
then succeeds, and different real tasks test later reuse. Counterexamples suspend
the old method. A real multi-field failure separately triggers original I's
sandboxed, bounded workflow generation and two subsequent Kernel-mediated uses.

Actual improvement is not a source-edit demonstration: the execution source
fingerprints remain unchanged within the recorded journey. Development fixes
(including a genuine deletion replay defect) are separately retained and are
never counted as Nana learning.

## Ownership and effect lifecycle

An exact target binds a private owned directory inode, PID, process-start token,
UID, socket inodes, instance ID and finite declared tasks. The client checks these
and SO_PEERCRED immediately before sending. The server rechecks root binding,
task revision, deadline and command scope. Writes use its pinned directory FD,
openat/renameat/fsync rather than trusting an arbitrary replacement pathname.

Each effect carries original action/subject/goal/plan/effect-slot, target binding,
finite allowed operations, expected digest, actual Grant/Budget references,
timestamp/deadline and idempotency. These references are audit data, **not** minted
authority. The original Kernel independently enforces the actual grants/budget.

An application acknowledgement is not success. Verify correlates effect receipt,
original request digest/action/subject, current target revision, and independent
document bytes or persisted form state. Missing receipt, concurrent alteration,
or channel/file disagreement remains UNKNOWN. No effect retry is inferred from
absence of evidence. Persisted effects are deduplicated; mismatching idempotency
input is rejected. A new application PID/binding is not automatically authorized.

Physical effect `SUCCEEDED` and task quality `FAILURE_VERIFIED` can coexist. For
example, an append can really happen but leave an unwanted old draft. We preserve
that external action and separately record why the actual goal failed.
