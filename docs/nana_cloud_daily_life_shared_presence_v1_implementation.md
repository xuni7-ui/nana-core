## Cloud lifecycle

A home is private and must not resolve through a symlink. The existing Store lock
and lease are acquired before an owned stale socket is removed. The socket is
0600; both endpoints check peer UID, and the client checks the server against the
current lease PID and socket inode. Readiness distinguishes a new lease with an
old unbound socket from a listening current process. A successful health probe
means process readiness only; it does not mean Beta approval.

One original selector processes control/user input ahead of background slices.
Requests and responses have byte bounds and receive deadlines. Disconnect after
send is UNKNOWN, not a cue to repeat. Connection failure before send is a separate
pre-dispatch error. SIGTERM uses normal stop; SIGKILL recovers original queue,
identity, lease epoch, existing work and decisions. Logs contain only state,
clock and queue depth and rotate into two bounded files. Disk pressure pauses
new work while status and stop remain available. Resources use existing RLIMIT,
affinity, cognition reservation and preemptible maintenance contracts.

A development service template has no credentials or Restart loop. It is an
uninstalled artifact, not production/systemd deployment. Host config chooses IANA
timezone; stored event time remains UTC microseconds. Quiet local hours affect
candidate delivery, not continued existence or the C normative decision.

## What changed in everyday work

The old document/form tasks remain intact. New CONTENT tasks deduplicate and sort
an explicitly supplied immutable input, writing a real owned document. New FILES
tasks move a finite declared set of files without overwriting a destination.
The application uses pinned directory FDs and a link/unlink sequence. A partial
operation can remain UNKNOWN; there is no global filesystem exploration, shell,
keyboard, desktop or arbitrary path interface.

Verification is independently read-only and compares persisted target state with
actual files, immutable source bytes, exact filenames and effect receipts.
Physical success differs from task-quality success. Existing real failures enter
Experience, original G evaluates preparation methods and later real transfer,
and counterexamples suspend strategies. Original I qualifies a bounded batch
workflow in its existing bwrap realm and later reuses it on real owned tasks.
Codex source fixes are separately recorded and never counted as Nana learning.

The combined finite journey uses11 task fixtures,12 adopted/revised goals,
42 Kernel actions and14 physical effects. Two deliberately unsupported
counterexample goals remain FAILED; they are not erased or misreported as all
success. Completed work leads to waiting/rest/no new tasks, not a task generator.
The preserved action/task/experience IDs permit independent audit.

## Shared life and entrance continuity

`SurfaceObservation` is a bounded PUBLIC/PROJECT application input with a
trusted host binding. Platform messages do not create Grant, role or governance.
Each platform event gets a stable canonical source identity; duplicates do not
replay model calls or judgments. A thread/topic/privacy collision is rejected.
An explicitly approved summary is a sourced user statement, not raw world truth.
Raw dialogue and rendered wording are not retained as permanent chat history.
The existing ContextAssembler receives relevant current source IDs, with bounded
selection and privacy filters; no second context builder is introduced.

QQ-like, Bili-like and CLI entrances project the same Subject and recent events.
The offline Bili adapter imports only the existing side-effect-free `normalize`
function. It does not start the legacy event pump, access accounts or run the
legacy agent. Actual metadata polling, incoming private content, account binding,
real delivery and production integration remain NOT_RUN/unauthorized.

SharedPresence offers only current, independently verified Experience records.
It checks actual result provenance, support, scope and privacy before offering a
finite source-backed cue. Original C can stay silent; the helper cannot decide
Nana must speak. The queue is capped by pending reviews and daily opportunity
limits. Re-reading an experience never becomes a new event stream after restart.

A later explicit review runs existing DeliveryAdmission with availability,
privacy and local quiet hours. An eligible assessment is still **shadow only**:
there is no send method or delivery Grant. Busy, refusal, deletion and changed
support prevent an old rationale from being reused. A changed availability source
may retire the old cycle and require new deliberation, rather than silently
replaying the prior desire. One-shot experience offers are deliberately conservative;
this version is not an automatic scheduled social-delivery service.

Primary User is inherited from the existing relational anchor; no role is inferred
from surface traffic or frequency. The developer reference user has no special
execution power. Relationship importance, social appetite and voluntary
accommodation retain original semantics. Manager stays negative-only and does
not rewrite the Subject's original wish.

## Recovery and portability

A combined smoke run found an actual integration defect: C could REFLECT for an
experience with no matching G method, but the completed reflection left a pending
intention. Combined with sharing, that exhausted the existing finite pending
capacity and deferred the last task. The fix settles the reflection only after
its sourced proposal exists. It does not adopt a lesson or change personality.

A durable follow-up marker also closes the C-commit/D-follow-up crash gap. On
recovery, the original committed cycle invokes existing idempotent adoption or
reflection services; C/model is not run again. Deleted support or expired authority
causes a durable review requirement, not blind retry. Actual SIGKILL tests cover
GOAL and REFLECTION immediately after the C commit, plus the independent runtime
restart test. Earlier failed evidence is preserved and is not presented as PASS.

Live and post-SIGKILL backups are consistent SQLite snapshots with the original
privacy sidecar and quarantine. They can be restored for integrity/history review;
they cannot become an unnoticed second writer. Running on a fresh host uses the
original B8 retirement/import/activation path. Source retirement remains permanent,
destination epoch exceeds the source floor, and old execution Grants are revoked.
An explicit pending-effects option preserves UNKNOWN, consumes HELD reservations
as SPENT and gives no new budget headroom. Default export still rejects unsettled
effects. No old intention or effect is automatically authorized on the new host.

This is not a distributed lease service or a fully automatic lost-host disaster
promotion protocol. A snapshot alone cannot prove the old host is fenced; that
case remains quarantined for trusted operational review. Stale backups cannot
silently replace a newer active home. Provider config, secret refs, sockets and
PID are host bindings, not portable personality. Historical effect provenance can
retain old artifact locations, but those locations are not active target bindings.

## Provider and dialogue gates

The existing configurable capability router already provides COGNITION, VISION,
STT, EMBED and other media operations. No permanent provider/model is chosen.
PUBLIC/PROJECT visibility, Core hard privacy, Provider/Route policy and cost/time
ceilings intersect. The new host hourly and per-provider daily limits count all
prepared attempts, including unresolved ones, before dispatch. Existing global
runtime reservations remain authoritative. Cost units are conservative estimates,
not verified relay billing.

A synthetic loopback swap test changes the configured model profile and version,
then restarts the same Subject. Context, source memory and old requested-model
provenance remain intact. A fixture initially returned the old model name and was
correctly rejected as CORRELATION_MISMATCH; correcting the fixture did not relax
the guard. Loopback is not a real provider or naturalness qualification.

A new real provider requires explicit current authorization and a safe host FD
or SecretResolver. No environment/history/key search occurs. The old UNKNOWN is
not retried or relabeled. Human naturalness and shared-life review must be performed
by the user; an unfilled structured worksheet is NOT_RUN. Without those gates,
FirstLife and Cloud Daily-Life Beta remain NOT_READY regardless of technical tests.
