# Genesis-success follow-up checklist (not a production approval)

1. Host Operator supplies actual canonical genesis subject/lineage receipt,
   pinned Core release, durable paths and health evidence. Run readonly preflight;
   a missing home, wrong identity, unsupported schema or invalid config must fail.
2. Do not relax original activation gate to run alongside legacy writers. Genesis
   is not activation: trusted fence/cutover/B1/backup approvals remain separate.
   Start/restart original bound home only through existing Supervisor. Validate
   same ID/lineage, lease epoch and pending UNKNOWN, never automatic creation.
3. Phone: private HTTPS identity-checked pairing → Reader/Conversation defaults →
   refresh → PROJECT chat → memories/state → disconnect → receipt-only verify →
   revoke → old binding rejected. No real QQ/Bili delivery. ANDROID_CONNECTED only
   after this happens on the actual phone, not loopback HTTP tests.
4. Provider: explicit safe FD/Resolver + approved endpoint/model/privacy + finite
   budget. One separately authorized PROJECT request must prove interpretation →
   original C judgment → reply, real IDs/usage when exposed, no authority minted.
   UNKNOWN means no retry/fallback and held budget. REAL_PROVIDER_PASS cannot be
   inferred from config writes or fixture ports. No paid call authorized here.
5. Life: observe original no-input wake/activity/rest, a source-backed concern,
   actual owned task outcome/experience, bounded G/I reuse, share candidate and
   BUSY/refusal/source-withdrawal suppression. Preserve original source references;
   development fixtures are not the user's shared history. Human reviews ordinary
   conversation/correction/disagreement before First-Life readiness.
6. Legacy: capture only an approved frozen snapshot, hash-only dry-run/dedup and
   conflicts first. Existing rehearsal importer is synthetic-only. Real private
   commit/export/retention/privacy and rollback/withdrawal need a separately
   reviewed authorized adapter; this task does not claim those gates complete.
7. B1: original Core consistent backup safe point → registered quarantine snapshot
   freeze → approved PC public recipient encrypt → explicit Tailscale/SSH send →
   independent PC restore verify. PC unavailable/unknown transport is not backup
   complete. New host must reauthorize ports/secrets/surfaces after any restore.

Evidence levels: OFFLINE_PASS (code/tests), REAL_PROVIDER_PASS (actual approved
model), HOST_DEPLOYED (actual operator receipts), ANDROID_CONNECTED (actual device),
FIRST_LIFE_READY (combined technical + user observed continuity). No lower level
is promoted into a higher one. Current task may only award OFFLINE_PASS.
